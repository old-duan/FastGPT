### 📝 更新内容

#### 🐛 Bug 修复

##### 1. 修复商业版 API 导致的服务崩溃 [CRITICAL]

- **问题**: 
  - 前端调用 `/proApi/support/user/inform/countUnread`
  - 该 API 为商业版功能,开源版不存在
  - 返回 404 并触发 HTML 错误页,导致未捕获异常
  - Node 进程崩溃退出

- **原因**: 
  - proApi 代理检测到循环调用,返回 HTML 而非 JSON
  - 前端未正确处理非 JSON 响应
  - 服务端未捕获异常

- **解决方案**:
  1. 创建开源版通知 API:
     - `projects/app/src/pages/api/support/user/inform/countUnread.ts`
     - 返回 `{ unreadCount: 0 }`
  
  2. 创建开源版系统消息 API:
     - `projects/app/src/pages/api/support/user/inform/getSystemMsgModal.ts`
     - 返回 `null`
  
  3. 修改前端调用路径:
     - 文件: `projects/app/src/web/support/user/inform/api.ts`
     - 从 `/proApi/support/...` 改为 `/support/...`

- **影响范围**: 
  - 解决服务频繁崩溃问题
  - 用户通知功能正常工作
  - 不影响其他模块

- **验证结果**:
  - ✅ 服务启动成功,无崩溃
  - ✅ API 正常响应
  - ✅ 前端正常加载
  - ✅ 稳定运行 2+ 小时

##### 2. 优化服务启动稳定性

- **问题**: 开发服务偶尔会自动关闭

- **原因**: 
  - 终端窗口关闭导致进程终止
  - 进程依赖启动终端生命周期

- **解决方案**:
  - 创建 `start-fastgpt-stable.ps1`
  - 使用 `Start-Process` 在独立窗口运行
  - 添加完整的前置检查
  - 实现进度显示和状态验证

- **效果**:
  - ✅ 服务稳定运行
  - ✅ 独立于启动终端
  - ✅ 无异常退出记录

如果部署出现问题,按以下步骤回滚:

