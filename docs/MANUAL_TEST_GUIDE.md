**解决方案**:
- ✅ 创建开源版 API: `/api/support/user/inform/countUnread.ts`
- ✅ 创建开源版 API: `/api/support/user/inform/getSystemMsgModal.ts`
- ✅ 修改前端调用路径: 从 `/proApi/...` 改为 `/support/...`

## 📋 手动测试步骤

### 前置条件确认

**1. 检查服务状态**
```powershell
# 检查 FastGPT
Get-Process -Name "node" -ErrorAction SilentlyContinue | Where-Object {$_.WorkingSet -gt 100MB}
netstat -ano | findstr ":3000.*LISTENING"

# 检查测试网站
netstat -ano | findstr ":8080.*LISTENING"

# 如果测试网站未运行,启动它:
cd D:\FastGPT\test-website
python -m http.server 8080
```

**2. 验证服务可访问**
- FastGPT: http://192.168.110.18:3000
- 测试网站: http://localhost:8080

### 步骤 1: 登录 FastGPT

1. 打开浏览器,访问: **http://192.168.110.18:3000**
2. 输入账号: `root`
3. 输入密码: `1234`
4. 点击登录

---

### 步骤 2: 创建 Web 站点知识库

1. 点击左侧导航栏的 **"知识库"**
2. 点击右上角 **"创建知识库"** 按钮
3. 在弹窗中:
   - **类型**: 选择 "Web 站点"
   - **名称**: 输入 "测试网站同步"
   - **向量模型**: 选择 "BGE-M3 (Ollama)" 或其他可用模型
   - **AI 模型**: 选择 "GLM-4" 或其他可用模型
4. 点击 **"确定"**

---

### 步骤 3: 配置 Web 站点同步

1. 进入刚创建的知识库 **"测试网站同步"**
2. 点击页面中的 **"站点配置"** 按钮
3. 填写配置参数:

   **基本配置**:
   - **根地址**: `http://localhost:8080`
     _(如果不行,尝试 `http://192.168.110.18:8080`)_
   
   **高级配置**:
   - **内容选择器**: `body` _(或留空使用默认)_
   - **排除选择器**: 留空
   - **最大爬取深度**: `5` _(默认值)_
   - **每次爬取数量**: `10` _(默认值)_

4. 点击 **"确认"** 按钮
   - 系统会先验证站点是否可访问
   - 如果失败,检查测试网站是否运行

---

### 步骤 4: 开始同步

1. 配置成功后,点击 **"开始同步"** 按钮
2. 在确认对话框中点击 **"确定"**
3. 观察页面状态:
   - 初始: "准备同步"
   - 进行中: "同步中" (显示进度)
   - 完成后: "已完成"

**预计时间**: 10-30秒 (取决于页面数量和内容)

## 🔍 故障排查

### 问题 1: "站点不可访问"

**检查**:
```powershell
# 测试本地访问
curl http://localhost:8080

# 测试网络访问  
curl http://192.168.110.18:8080
```

**解决**:
1. 确保测试网站服务器运行: `python -m http.server 8080`
2. 如果使用 localhost 失败,改用 `192.168.110.18:8080`
3. 检查防火墙设置

---

### 问题 2: "同步任务无响应"

**检查服务器日志**:
在 FastGPT 服务窗口查找:
```
[Info] Init Dataset Sync Worker...        ← Worker 已启动
[DatasetSync] Start syncing dataset: xxx  ← 同步开始
[DatasetSync] Found X collections         ← 发现集合
[DatasetSync] Dataset sync completed      ← 同步完成
```

**可能原因**:
1. Worker 未正确初始化 → 重启 FastGPT
2. Redis 连接问题 → 检查 Redis 服务
3. BullMQ 队列阻塞 → 查看队列状态

**解决步骤**:
```powershell
# 1. 检查 Redis
docker ps | findstr redis

# 2. 重启 FastGPT
Get-Process -Name "node" | Stop-Process -Force
& "D:\FastGPT\start-fastgpt-stable.ps1"

# 3. 重新尝试同步
```

---

### 问题 3: "集合创建但无数据块"

**可能原因**:
- 网页内容为空
- 选择器配置错误  
- 分块处理失败
- 向量生成失败

**检查**:
```powershell
# 访问原始页面
Invoke-WebRequest -Uri "http://localhost:8080/index.html"

# 检查 Ollama
curl http://192.168.110.18:11434/api/tags
```

**解决**:
1. 确认网页有实际内容
2. 调整内容选择器 (尝试 `main`, `article`, `body`)
3. 检查向量模型是否可用
4. 查看服务器日志中的错误信息

---

### 问题 4: "向量生成失败"

**检查 Ollama 服务**:
```powershell
# 测试 Embedding 模型
curl -X POST http://192.168.110.18:11434/api/embeddings `
  -H "Content-Type: application/json" `
  -d '{"model":"bge-m3:latest","prompt":"test"}'
```

**解决**:
1. 确认 Ollama 服务运行
2. 确认 Embedding 模型已下载
3. 检查模型配置是否正确
4. 查看服务器日志中的向量生成错误

---

### 问题 5: "检索无结果或结果不准确"

**调试步骤**:
1. 检查数据块是否有向量 (应显示"已生成")
2. 降低相似度阈值 (0.3 → 0.2)
3. 使用更直接的问题测试
4. 检查向量维度是否匹配

**优化建议**:
- 调整分块大小 (默认512 tokens)
- 优化内容选择器,过滤无关内容
- 使用更好的向量模型
- 增加训练数据量
